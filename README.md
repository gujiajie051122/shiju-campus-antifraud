# 识局 · 校园反诈演练（单场景验证版 v0.2）

当前交付是“兼职招聘”可运行版本，包含风险和正常招聘对照，用于验证交互与记录规则。尚不是完整参赛作品，也不构成防骗能力认证。

## 本机启动
需要 Node.js 22.13 以上。依赖已安装，可直接双击“启动识局.cmd”，或运行：

```powershell
npm run dev -- --host 127.0.0.1 --port 5173
```

浏览器打开 http://127.0.0.1:5173 。保持启动窗口打开。第一次从源码安装需联网运行 npm install。

## 体验路径
1. 选择模式后开始练习，随机进入风险或正常情境，开始时不揭示分组。
2. 查看岗位和编号，自由提问；可记下联系人身份、报酬与结算等待确认项。
3. 主动查看“入职要求说明”。在独立核实中输入岗位编号 QH-061 或联系人称呼“林老师”，或选择回拨号码的来源。输错查询和对方提供的号码不计为独立核实。
4. 选择暂停、继续、退出或模拟报告，确认后复盘。
5. 先对照联系人说法与已取得的独立结果；未取得的材料保留待确认状态。完整记录默认收起，可从评价依据跳转展开，再填写自己的解释。
6. 重演要求前节点：原分支保留，节点后的信息清除，之前取得的信息保留。
7. 切换对照练习后旧练习进入往期记录。最近20组保存在当前浏览器；长期保存请导出JSON，包含所属的重演前分支。
8. 复盘下方展开“查一条建议”，查询兼职费用、身份与回拨渠道等问题；每一点可展开资料摘要、段落定位、日期和原文链接。资料不足时不生成答案。

## 可选账号配置
无需账号即可运行文字版。复制 .env.example 为 .env.local，仅在本机填写，重启服务生效。

- LLM_BASE_URL：HTTPS兼容Chat Completions的API基址，程序追加 /chat/completions。
- LLM_API_KEY / LLM_MODEL：服务端模型密钥与模型名。模型收到最近8条交流和程序提供的可见事实，不接收未打开的费用卡或正常/风险组标签。模型文本不会触发核实、决定或改变状态；服务失败、结构不合格、虚构数字等情况回退预设回复。
- LLM_OUTPUT_FORMAT：默认schema，需要服务和模型支持严格JSON Schema；仅支持JSON模式的兼容服务可选json，两种模式均做本地字段和引用校验。未指定服务商或默认付费模型。
- DID_AGENT_ID / DID_CLIENT_KEY：数字人Agent ID及浏览器用公开client key。必须在服务商后台限制来源域名，不可填账号API secret。只使用自有或获授权的虚构角色。

模型密钥不会返回浏览器；公开client key按SDK设计由浏览器使用。不要提交 .env.local 或在聊天中发送密钥。托管站点需单独配置运行时环境，本机配置不会修改线上环境。

## 检查命令
```powershell
npm run typecheck
npm test
node tests/http-check.mjs
npm run build
```
HTTP检查需开发服务器在5173运行，可通过 CHECK_URL 指定地址；无论是否配置模型，该脚本均不发起供应商请求。59个自动检查覆盖场景、模型约束、服务异常、检索、输入边界、配额与并发，其中一项遍历256种决策与核实组合。配额测试使用Node 24内置SQLite，包含12个独立连接的并发竞争测试；运行全部测试需要Node 24。自动检查中的模型响应为受控测试数据；真实联调另行记录，不等同于大样本质量或训练效果验证。

引用编号校验能排除不存在的来源，不能证明模型每句话都被原文支持；事实与引用的语义一致性仍需教师审校和真实模型评估。检索资料是人工整理摘要，不是实时互联网搜索，也不对现实案件作违法认定。

## 核心代码
- app/page.tsx：演练、复盘、记录、设备设置。
- lib/scenario.ts：确定性情境、事件、核实、检查点与复盘。
- lib/avatar.ts：数字人适配，只用speak播报场景控制后的回复，不使用服务商聊天代理。
- app/api/dialogue：受控对话与模型降级。
- lib/dialogue.ts、lib/model-service.ts：可见事实、对话上下文、结构化输出与回退。
- lib/knowledge.ts、lib/knowledge-answer.ts：可追溯语料、BM25检索、模型整理与引用校验。
- app/components/KnowledgeDesk.tsx、app/api/knowledge：复盘内资料查询。
- lib/reflection-context.ts、lib/reflection-answer.ts、app/api/reflection：从限定的操作事实与自述候选中选择复盘重点；模型只返回候选ID，不自由编造心理解释。无自述、否定/假设等模糊表达不推断影响因素。
- app/components/ReflectionDesk.tsx、lib/reflection-practice.ts：依据展开、可修改的确认/否定/不确定、6道原创异题练习（3个方向各2题）。仅用户确认的因素可影响练习方向；否则按操作缺口选题。修改已保存自述使旧整理失效，重演归档原记录，JSON导出包含确认与练习记录。
- AI复盘须勾选同意后发送本轮操作代码与最多500字已保存自述，不发送聊天原文或往期记录。用户自行填写内容仍可能包含个人信息，保存前应检查。模型未配置或调用失败保留操作摘要和免模型练习；不声称心理原因或训练效果已经得到验证。
- app/api/status、app/api/avatar：服务状态和公开SDK配置。
- lib/ai-budget.ts、app/api/usage：持久化配额、并发租约、个人用量；db/schema.ts与drizzle为数据库结构和迁移。

## 调用额度与用量

对话、资料整理和AI复盘共用每人每日40次、全站每日200次的模型请求上限，北京时间零点更新。每人每分钟最多6次、间隔至少1.5秒、同一时间最多1次；全站同时最多3次。通过服务端环境变量AI_USER_DAILY_LIMIT、AI_SITE_DAILY_LIMIT、AI_USER_PER_MINUTE、AI_MIN_INTERVAL_MS、AI_SITE_CONCURRENT调整；次数或并发上限填0会停止模型调用，间隔填0只取消最短间隔检查；非法值拒绝模型调用。正常使用预设回复、费用卡未打开的提示、明确拒绝和无命中资料不消耗次数。

按托管平台认证用户ID的站内散列计数，不依赖浏览器本地存储。未登录、不具备用户身份的服务访问、数据库缺失或异常均不向模型发请求，保留预设流程。私有站点正常登录后自动获得身份。本机预览可在“服务与设备”里登录本机测试身份；不要将本机预览直接公开到互联网。

数据库使用单条带条件INSERT预约，避免并发请求绕过上限；超时遗留预约45秒后释放并发位置。发起请求即占一次，供应商失败、输出不合格、取消均不退还，防止反复失败绕过限额；取消会保留并发租约直到到期。仅记录时间、功能、模型、用户散列、HTTP状态、处理结果和Token数，不保存提示词、完整对话、密钥、邮箱或IP。供应商未报告Token时保存空值，不虚构费用或用量。网络中断时供应商可能仍计费，因此不能承诺取消即免费。统计用于运维，不是防篡改学习证据。

Sites部署时自动创建DB并应用schema-only迁移。本机首次生成构建后执行：
```powershell
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_lucky_hammerhead.sql
```
不要重复执行已应用的迁移。之后重启或刷新不会重置当日用量。每次打开“服务与设备”读取最新个人用量；不同用户不能读取彼此日志。

请求次数保护不能替代供应商计费设置，当前也未接入供应商的实时账单或余额。真实花费还取决于输入输出长度、模型单价、其他账号调用和数字人服务。正式开放前需要结合供应商额度保护、预警与实际账单验证预算。
